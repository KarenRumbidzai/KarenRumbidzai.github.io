AI as a Team Member: A TPM's Guide to Adding an AI Agent to Jira

Artificial intelligence is changing how software teams work. But one of the most interesting developments isn't simply asking AI questions or using it to generate code. It's giving an AI agent a defined task and allowing it to participate in a team's delivery workflow.

Imagine creating a Jira ticket, assigning it to an AI coding agent, and having that agent inspect a codebase, implement a change, run tests and open a pull request for review.

This is possible with compatible AI agents and the right integrations. It isn't a standard capability of every Jira installation, however.

So, how does a Technical Project Manager (TPM) make this work?

1. Understand what an AI agent is

A chatbot responds to questions. An AI agent can go further: it can use connected tools to perform a sequence of actions towards a defined goal.

Depending on its capabilities and permissions, an AI coding agent might:

  • Read an assigned Jira ticket.
  • Inspect relevant files in a GitHub repository.
  • Implement a requested change.
  • Run tests or other validation commands.
  • Create commits and push a branch.
  • Open a pull request for human review.

The important distinction is that an agent's capabilities depend on its tools, integrations, environment and permissions. Connecting an AI assistant to Jira does not automatically give it access to GitHub or the ability to change code.

2. Decide what role the agent will play

Treat the agent like a team member with a defined responsibility, not an unrestricted developer.

For example:

Role: AI coding assistant
Responsibilities: Implement small, well-defined development tasks, run available checks and report its findings.
Boundaries: It must not invent requirements, expand the agreed scope or merge its own changes into the main branch.

The TPM remains responsible for ensuring the task is appropriate, the requirements are clear and the work follows the team's delivery process.

3. Connect the tools

A basic workflow involves three components:

  • Jira: Where the team defines, assigns and tracks work.
  • GitHub: Where the source code, branches, commits and pull requests live.
  • AI coding agent: The tool that interprets the task and performs the authorised work.

One possible setup uses Jira with an appropriate coding-agent integration, GitHub for source control and a compatible agent such as GitHub Copilot coding agent.

Other configurations may use Atlassian Rovo or a separate AI agent with the necessary integrations. The exact setup differs by product.

The key question is: can the chosen agent read Jira issues, access the intended repository and perform the specific actions the team expects?

Verify these capabilities before designing the workflow around them.

4. Give the agent only the access it needs

An AI agent should not automatically receive administrator access simply because it is part of the workflow.

Depending on the integration, it may need permission to:

  • Read the relevant Jira project and issues.
  • Access a specific GitHub repository.
  • Create a working branch or use an authorised existing branch.
  • Commit and push changes.
  • Open pull requests.

Reading code, pushing changes, approving a pull request and merging it are separate capabilities. Configure and verify each one independently.

Use the least privilege necessary, protect credentials and secrets, and follow the organisation's access policies.

5. Establish the rules before assigning work

The agent needs clear operating instructions.

For example:

  • Work only on the assigned Jira issue.
  • Follow the stated acceptance criteria.
  • Do not assume missing requirements.
  • Ask for clarification when a decision would affect scope or behaviour.
  • Do not expose credentials or modify secrets.
  • Run the relevant tests and report any failures.
  • Open a pull request with a summary of changes and validation results.
  • Do not merge changes without the required human approval.

These rules reduce ambiguity, but they do not guarantee correct behaviour. The team must still monitor the agent's output.

6. Define what success looks like

A completed ticket should mean more than “the AI wrote some code.”

The expected outcome might include:

  • The requested change has been implemented.
  • Acceptance criteria have been checked.
  • Relevant automated tests have run.
  • Known failures or limitations have been documented.
  • A pull request is available for review.
  • A human reviewer has assessed the changes.

The TPM can then track the work through the same delivery process used for other team contributions.

The takeaway

Adding an AI agent to Jira is not merely a configuration exercise. It is a delivery decision involving responsibilities, access, quality controls and accountability.

The goal is not to remove humans from software development. It is to let AI handle appropriate execution tasks while humans retain control over requirements, technical decisions, risk and approval.
