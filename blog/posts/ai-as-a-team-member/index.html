Who's Working on This Ticket? Introducing Your AI Teammate

Part 1 of 3 25 Oct 2026 ·6 min read
technical-project-managementartificial-intelligencejiraai-agentsagilesoftware-delivery

It's stand-up. Someone asks, "Who's picking up APP-142?" and the answer is: the AI agent.

That's no longer science fiction. With the right integrations, you can assign a Jira ticket to an AI coding agent and it will read the ticket, look through the code, make the change, run the tests and open a pull request for someone to review.

But it doesn't come out of the box with every Jira setup, and it doesn't run itself. Someone has to decide what the agent is allowed to do, and what it must never do. That someone is usually the Technical Project Manager (TPM).

In this part

🤖 What an AI agent actually is  ·  🪪 Its job description  ·  🔌 The three tools you connect  ·  🔐 How much access to give it  ·  📜 House rules  ·  🏁 What "done" means

🤖 A chatbot answers. An agent acts.

A chatbot replies to your questions. An agent uses connected tools to carry out a series of steps towards a goal.

Given the right tools and permissions, an AI coding agent can:

  • Read the Jira ticket assigned to it.
  • Look through the relevant files in a GitHub repository.
  • Make the requested change.
  • Run tests and other checks.
  • Commit the work and push a branch.
  • Open a pull request for a human to review.

What it can do depends on what you connect. Linking an AI assistant to Jira doesn't give it access to GitHub, and it doesn't let it change code. Every capability comes from a specific tool, integration or permission.

🪪 Give it a job description

Treat the agent like a new team member with a clear role, not a developer with the keys to everything.

  • Role 🤖

    AI coding assistant

    Picks up small, well-defined development tasks.

  • Does 🛠️

    Builds, checks, reports

    Makes the change, runs the available checks and tells you what it found.

  • Never 🚫

    Invents, expands or merges

    It doesn't make up requirements, quietly grow the scope or merge its own work into the main branch.

The TPM's job doesn't go away. You still make sure the task suits the agent, the requirements are clear and the work goes through the team's normal delivery process.

🔌 Connect the three tools

A basic setup has three parts:

  • 🗂️

    Plan

    Jira

    Where the team writes, assigns and tracks the work.

  • 🐙

    Build

    GitHub

    Where the code, branches, commits and pull requests live.

  • 🤖

    Do

    The AI coding agent

    Reads the task and does the work it's been authorised to do.

🧩 Which tools can actually do this?

There's no single standard setup. A few common options:

  • Jira + GitHub Copilot coding agent, connected through a supported coding-agent integration.
  • Atlassian Rovo, Atlassian's own AI, where your plan and configuration support it.
  • Another AI agent that has the integrations it needs for Jira and GitHub.

Products change quickly, so check each vendor's documentation for what's supported today.

One question to answer before anything else: can this agent read Jira issues, reach the right repository, and carry out the specific actions you expect? Test each one before you design your workflow around it.

🔐 Give it only the access it needs

Being part of the workflow doesn't mean the agent gets admin rights. Reading code, pushing changes, approving a pull request and merging it are all separate permissions. Set up and test each one on its own.

Permission Give it?
📖 Read the relevant Jira project and issues ✅ Yes
📂 Access one specific GitHub repository ✅ Yes
🌿 Create a working branch, or use one you've approved ✅ Yes
📤 Commit and push changes ✅ If authorised
🔀 Open pull requests ✅ Yes
👍 Approve pull requests ❌ No, that's for a human
🚀 Merge into the main branch ❌ No, that's for a human
🔑 Production systems and secrets ❌ No

Start with the least privilege that gets the job done. Keep credentials and secrets out of reach, and follow your organisation's access policies.

📜 Set the house rules before the first ticket

The agent needs clear operating instructions. Write them once, and include them with every task:

House rules for the AI coding agent

- Work only on the Jira issue assigned to you.
- Follow the acceptance criteria in that issue.
- Don't fill in missing requirements yourself.
- Ask for clarification when a decision would change scope or behaviour.
- Never expose credentials or change secrets.
- Run the relevant tests and report any failures.
- Open a pull request that summarises the changes and the test results.
- Never merge without the required human approval.

Rules cut down on guesswork, but they don't guarantee good behaviour. Someone on the team still has to check what the agent produces.

🏁 Agree on what "done" looks like

A finished ticket means more than "the AI wrote some code". Before you close it, you should be able to tick every box:

  • The requested change has been made.
  • Each acceptance criterion has been checked.
  • The relevant automated tests have run.
  • Known failures and limitations are written down.
  • A pull request is ready for review.
  • A human reviewer has looked at the changes.

From there, the TPM tracks the work through the same delivery process as everyone else's.

The takeaway

Adding an AI agent to Jira isn't just a configuration task. It's a delivery decision about responsibilities, access, quality and accountability.

The point isn't to take humans out of software development. It's to hand the agent the right execution work, while people keep control of the requirements, the technical decisions, the risk and the final approval.
